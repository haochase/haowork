Why Haowork

Agent 让开发更快，工程治理必须跟上

三个真实行业工作过程，说明 Haowork 补足 AgentTeams 当前不负责的需求治理、责任追溯、人工审批和跨环境可信迁移能力。

场景 01银行 · 证券 · 军工 · 涉敏研发

公网研发与隔离内场持续开发

公网环境模型能力强、工具丰富，隔离内场掌握真实数据和长期运维责任。项目迁移后必须更换 Agent、模型与运行身份，但不能让前期设计和责任链随环境一起丢失。

实际问题

完整仓库和凭据不能随意出域；仅靠 Git 又难以表达 Goal、架构约束、任务划分、审批与失败过程。换 Agent 后容易从最近一次指令重新理解项目。

Haowork 介入

筛选经批准的最小工程事实，生成签名 Capsule；目标环境验签、预览并由 Human 再批准，随后重新绑定本地 Agent、租约、Scope 和 Skill。

可核验结果

不迁移凭据、私有记忆和完整项目，也能延续 GoalVersion、Context、责任、审批和 Trace 关系；目标区生成新的运行证据。

  1. 01公网工程事实Goal · Design · Trace
  2. 02Human 审批白名单与风险确认
  3. 03签名 Capsule摘要 · 来源 · 目标区
  4. 04隔离区预览验签 · 冲突检测
  5. 05运行时重绑定Agent · Lease · Scope
  6. 06新 Trace内场继续开发
场景 02多人小团队 · 高频 AI Coding

高频 AI Coding 的团队偏差审查

Agent 的编码速度已经超过人工逐文件审查能力。多人持续追加需求时，最近一次对话很容易覆盖早期约束，责任边界和最初设计在不知不觉中漂移。

实际问题

开发者分别向 Agent 下达任务，人的记忆和审查带宽有限；Agent 可能迎合最近指令，模块 Scope、完成标准和验证责任逐渐偏离最初设计。

Haowork 介入

把需求版本、负责人、Mission、租约、Scope、审批、执行 Trace、独立验证和 Git 结果关联起来；冲突先进入候选状态，不直接成为完成事实。

可核验结果

团队无需逐文件重读全部代码，也能从摘要、差异和风险级别定位偏差；Human Owner、Lead、Reviewer 只在关键决策点介入。

  1. 01Human Goal需求与完成条件
  2. 02受限 Mission责任 · Scope · Lease
  3. 03AgentTeams 分工Research · Build · Verify
  4. 04Build 候选代码与制品摘要
  5. 05独立验证测试 · 基线 · Evidence
  6. 06Human 决策批准 · 拒绝 · 纠偏
场景 03历史系统 · 开源二次开发 · 人员交接

历史项目设计根因与重构影响追溯

接手公司历史系统或基于开源项目二次开发时，原作者可能已经离开。Git 能回答代码改了什么，却经常无法回答当时为什么选择这种设计。

实际问题

提交信息只能覆盖部分原因；跨系统约束、失败方案、人工审批和验证依据散落在人员记忆、对话和文档中，重构影响很难准确估算。

Haowork 介入

从代码变更或制品引用反向定位 Trace、Mission、Context、Approval 和原始 GoalVersion，并标出当时的责任人、风险级别和验证结果。

可核验结果

接手者能看到功能存在的根本原因、仍然有效的约束和影响范围，在重构前判断哪些决策需要重新验证或重新审批。

  1. 01代码 / 制品Commit · Artifact
  2. 02执行 TraceActor · 时间 · 摘要
  3. 03Mission任务 · Scope · Agent
  4. 04Context / Approval约束与人工决策
  5. 05原始 Goal需求根因
  6. 06影响分析重构成本与风险

Division of Responsibility

执行与治理分层，各自承担不可替代的责任

Haowork 不重造多智能体框架；它向 AgentTeams 下发受约束的工作合同，并接收执行事件和制品引用作为治理证据。

Haowork / 治理平面

Haowork 负责工程治理

  • GoalVersion 与上下文边界
  • Mission、租约、Scope 与风险审批
  • Trace、Evidence、Conflict 与 Recovery
  • 跨环境签名迁移与目标区重新绑定
受限 Mission 下发执行事件回流制品引用回流
AgentTeams / 执行平面

AgentTeams 负责多智能体执行

  • Manager 分解和协调 Mission
  • Delivery Leader 维护依赖与交付节奏
  • Research、Build、Verify 职能分离
  • Matrix 协作、MinIO 制品与运行时状态

AgentTeams Runtime

五个运行职能，绑定同一个受治理 Mission

角色不是页面装饰，而是不同权限、输入、输出和验证责任的运行时身份。

01Manager接收 Mission、建立 Team、协调状态
02Delivery Leader维护依赖、节奏和交付边界
03Research提取约束、基线和证据上下文
04Build在 Scope 内生成候选变更
05Verify独立验证并提交 Evidence
同一 Mission Hash独立 Runtime Binding角色级 Skill AllowlistTrace 全程回流
