# P0-05 v1.2.2 物理双区离线交接手册

## 目标与边界

本手册用于验证 Windows Public 与 Ubuntu Internal 两个独立 AgentTeams 环境之间的受治理离线交接。
两区不建立 Matrix 联邦、共享 MinIO、共享 Higress、共享 Team Core、实时隧道或业务 SSH/SCP 通道。
SSH/SCP 只可用于部署准备和测试控制，正式交接只能由人工搬运签名文件及其 SHA-256 收据。

Haowork 负责签名 Capsule/Return、目标区逻辑身份重绑定、审批门禁、冲突分类和交接收据；
AgentTeams 仍负责本区 Manager、Delivery Leader 与 Worker 的执行和事件产生。

## 运行前置条件

1. 两区分别部署官方 AgentTeams v1.2.2 组件及独立的 Matrix、MinIO/S3、Higress、Core Bridge。
2. 两区均有独立的模型、Matrix、对象存储和运行身份；不得复用 Public 的 token、room 凭据、S3 凭据或模型 key。
3. Public 信任 Internal 的 Return 公钥，Internal 信任 Public 的 Capsule 公钥。私钥只保留在本区的受控 Core host，不进入 Git、Capsule、Return、Trace、命令行参数或终端输出。
4. 受控 Core host 提供 `transfer.Service` 所需签名、可信来源、运行绑定解析和审批验证能力。标准 `haowork` CLI 不会自行读取私钥；能力缺失时必须返回 `transfer_unavailable` 或 `ExitOffline`。
5. 使用允许的离线介质或受控交接目录。收据目录应位于各区项目的 `.haowork/cache/evidence/p0-05-v1.2.2/offline/`，不得提交到 Git。

## 文件交接链路

```text
Windows Public Core
  -- signed Capsule + public-export receipt --> [人工离线介质]
Ubuntu Internal Core
  -- signed Return + internal-return receipt --> [人工离线介质]
Windows Public Core
  -- preview, owner approval, public-merge receipt --> governance ledger
```

每个收据包含 `schema_version`、阶段、Transfer ID、来源/目标环境、文件名、SHA-256 和记录时间。
脚本在导入前验证环境映射与文件哈希；篡改文件、错误区文件或错误阶段都会失败关闭。

## 四个操作阶段

以下命令中的 `HaoworkBinary` 是受控 Core host 可用的 Haowork CLI 路径。不要把任何密钥写入命令行。

### 1. Windows Public 导出

导出请求由 Public Core 生成，包含已经批准的 Mission、Context、Lease、Trace、允许的制品和最小 Git 事实。

```powershell
powershell.exe -NoProfile -File .\scripts\p0-05-v122-public-export.ps1 `
  -HaoworkBinary .\haowork.exe -Project <public-project> `
  -Request <public-export-request.json> -Output <capsule.zip> `
  -ReceiptDirectory <public-offline-evidence>
```

脚本只生成文件和收据。搬运 `capsule.zip` 与对应收据是人工步骤，不应替换为业务 SCP。

### 2. Ubuntu Internal 预览、审批与导入

先在 Internal Core 预览。预览不写治理事实；确认目标运行身份、范围、目标环境和过期时间后，Owner 再加入 `-Confirm`。

```powershell
pwsh -NoProfile -File ./scripts/p0-05-v122-internal-import.ps1 `
  -HaoworkBinary ./haowork -Project <internal-project> -Capsule <capsule.zip> `
  -OwnerActor <internal-owner-id> -ReceiptDirectory <internal-offline-evidence>

pwsh -NoProfile -File ./scripts/p0-05-v122-internal-import.ps1 `
  -HaoworkBinary ./haowork -Project <internal-project> -Capsule <capsule.zip> `
  -OwnerActor <internal-owner-id> -ReceiptDirectory <internal-offline-evidence> -Confirm
```

导入会保留逻辑 Agent ID，但必须重绑定为 Internal 的 runtime principal、AgentTeams instance 和本区凭据。

### 3. Ubuntu Internal 生成 Return

Internal Core 先记录针对 Return 内容哈希的人工审批。脚本只接受该批准请求，并由 Internal Core 签名输出。

```powershell
pwsh -NoProfile -File ./scripts/p0-05-v122-internal-return.ps1 `
  -HaoworkBinary ./haowork -Project <internal-project> `
  -Request <approved-return-request.json> -Output <return.zip> `
  -ReceiptDirectory <internal-offline-evidence> -Confirm
```

Return 只包含已批准的补丁、验证结果、受信任制品摘要和最小 Trace 引用。未批准条目不会进入归还包；冲突分类随命令结果输出。

### 4. Windows Public 预览与合并

Public 区同样先预览 Return；Owner 确认后才将目标区运行身份重绑定和导入事实写入治理账本。

```powershell
powershell.exe -NoProfile -File .\scripts\p0-05-v122-public-merge.ps1 `
  -HaoworkBinary .\haowork.exe -Project <public-project> `
  -ReturnArchive <return.zip> -OwnerActor <public-owner-id> `
  -ReceiptDirectory <public-offline-evidence>

powershell.exe -NoProfile -File .\scripts\p0-05-v122-public-merge.ps1 `
  -HaoworkBinary .\haowork.exe -Project <public-project> `
  -ReturnArchive <return.zip> -OwnerActor <public-owner-id> `
  -ReceiptDirectory <public-offline-evidence> -Confirm
```

存在 `stale_goal`、`lease_reassigned`、`scope_overlap`、`design_diverged`、
`evidence_mismatch` 或 `terminal_state` 时，必须由 Owner 决定后续处置；脚本不会自动提交或自动合并代码。

## 网络隔离证明

该脚本只读测试 TCP 连通性，不会修改路由或防火墙。每侧都列出本区应可达服务和对端应不可达服务；格式为 `name=host:port`。

```powershell
powershell.exe -NoProfile -File .\scripts\p0-05-v122-network-proof.ps1 `
  -Side Public `
  -LocalEndpoint 'public-core=127.0.0.1:8081' `
  -OppositeEndpoint 'internal-matrix=<internal-host>:6167','internal-minio=<internal-host>:9000' `
  -EvidencePath <public-offline-evidence>\network-proof-public.json
```

任何本区端口不可达或对端端口可达都会返回非零。若需要配置防火墙，脚本只报告失败；由环境负责人单独审批并执行变更。

## 本地自动验证与物理验收

本地自动验证：

```powershell
$env:TEMP = 'E:\haochase\haowork\.haowork\cache\tmp'
$env:TMP = $env:TEMP
go test ./internal/e2e -run TestOffline -count=1
powershell.exe -NoProfile -File .\scripts\p0-05-v122-offline.tests.ps1 `
  -TempRoot 'E:\haochase\haowork\.haowork\cache\offline-tests'
```

这些命令证明离线状态机和脚本收据协议，不能证明物理双机环境已经通过。只有在两台机器分别保存收据、网络证明和脱敏运行证据后，才能把状态标记为 `PHYSICAL_DUAL_ZONE_VERIFIED`；缺少任一前置条件时必须标记 `BLOCKED_PHYSICAL_ENVIRONMENT`。
